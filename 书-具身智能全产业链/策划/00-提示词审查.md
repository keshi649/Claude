# 提示词审查与改写

用户给了一份《具身智能全产业链书籍总提示词》，并说："以上的提示词会有许多错误，不仅是给你的指令有错误，知识也有错误，逻辑也有错误……你自己审查发现并优化，再给我出书。"

这份文件做三件事：一、逐条列出查到的问题，分成"指令""知识""逻辑"三类，并写明怎么处理；二、说明哪些看起来可疑、联网核实后其实是对的（避免把对的改错）；三、给出改写后的总提示词，本书按它执行。

核查日期 2026-11-07。出处都在 `资料/事实库.md`。

### （三）逻辑与结构

1. **卷的顺序**：原结构"场景 → 机器 → 部件 → 编年史 → 公司"。第一卷每章都要写"适合的身体、技术栈、成熟度"，可读者这时还不知道机器类型、部件和模型是什么，只能大量往后引用或者先讲一遍；而解释"为什么今天是这个样子"的编年史放在第四卷，因果关系来得太晚。改成：**地图 → 来路（编年史）→ 身体 → 部件与供应链 → 大脑 → 场景 → 牌桌**。场景放在后面，正好能用前面讲过的东西算账和判断成熟度；公司放最后，因为一家公司的位置要用供应链、技术路线和证据阶段三把尺子一起量。
2. **重复**：原结构里同一家公司会在场景卷、机器卷、部件卷、公司卷各出现一次。改成"一处详写、别处引用"：公司详情在第七部和附录 B，部件供应商在第四部和附录 C。
3. **自相矛盾的重心**：原文警告"不能把一家公司内部迭代史误当作行业技术史"，却把最详细的指令给了 Physical Intelligence 一家。改成 PI 作为第 19 章里的一个案例，和 Google DeepMind、NVIDIA、Figure、宇树等同列比较。
4. **自动驾驶**：原文一边说"不把自动驾驶直接等同于具身智能"，一边把它同时列为一个场景和一种机器。自动驾驶本身就是一个比人形机器人大得多的行业，展开写会让书失焦。改成一章"相邻的路"：只写哪些东西可以迁移（数据闭环、端到端、仿真、安全论证），哪些不能。
5. **无人机、水下机器人**：同理，各自是独立产业，放进"其他身体"一章做对照。
6. **"代表性筛选"五问**：思路很好，但对每个节点都做满会让编年史读不下去。改成只对主干节点做，并在正文里明确写出"同期的替代路线是什么、为什么选它"。
7. **编辑过程写进正文**：原文要求的很多输出（研究包、图片卡、新增实体清单）是给作者和编辑用的。它们照做，但放在 `策划/` 和 `资料/`，不印进书里。

## 三、改写后的总提示词

> 下面是本书实际执行的版本。

### 角色与目标

你是本书的作者、研究员和事实核查编辑。用联网检索和本仓库的文件，写一本简体中文的技术产业书《具身智能：机器、部件与全产业链》，署名甜菜。读者懂一点 AI、软件、硬件和商业，但不是具身智能的业内人；他们想弄清楚：这些机器从哪来、由什么组成、谁在造、走到了哪一步、哪些话可以信。覆盖全球，重点比较中国和美国，补充欧洲、日本、韩国。

### 全书统一的规矩

1. **一个截止日**：资料截止 2026-11-07。正文写"截至某年某月"时都带日期；截止日之后的事不写。
2. **证据和断言要匹配**（这是全书的方法论，第 2 章专门讲）：

| 想证明什么 | 够格的证据 | 不够格的证据 |
|---|---|---|
| 一个方法有效 | 论文＋公开代码或权重、第三方复现 | 公司博客里的视频 |
| 机器人能做某个任务 | 说明是否遥操作的无剪辑长视频、条件公开的重复测试、第三方评测 | 一段剪辑过的演示 |
| 有客户在试用 | 客户自己的公告或采访 | 机器人公司的单方面说法 |
| 卖出去了 | 有约束力的合同公告、财报里的收入 | 意向书、框架协议、"战略合作" |
| 规模量产 | 财报或招股书里的产量、销量，监管文件 | 规划产能、"百万台"目标 |

3. **来源分四级**：A 独立可核验（第三方测试、认证和标准机构、政府统计、客户方的公开说明、经审计的财报）；B 当事方的正式文件（论文和代码、招股书和 SEC 申报、公司公告、产品文档）；C 高质量媒体的报道和采访；D 宣传视频、演讲、社交媒体、二手转述、聚合网站。D 级只能证明"有人这么说过"。
4. **阶段梯子**：R 研究 → D 演示 → T 可重复测试 → P 客户试点 → O 有约束力的订单 → L 已交付（必须注明用途：科研教育展示，还是生产作业）→ M 多个客户在生产作业中长期使用。另有一条**生产规模**轴：样机、小批（百台级）、批量（千台级）、规模量产（万台级以上并持续）。同一家公司的不同产品分别标。
5. **不替人说话**：不把会识别写成会操作，不把会操作写成能长期部署，不把交付写成量产，不把设计产能写成产量；"首个""通用""量产"这些词，只在引述时出现，并且说明是谁说的。
6. **查不到就说查不到**：写"尚未公开""公开证据不足"或"各方说法不一"，并进入附录 F 待核实清单。

### 结构（七部）

第一部 地图（什么是具身智能；怎么读一条机器人新闻）→ 第二部 来路（1940 年代到 2024 年的技术谱系，控制与身体、感知与环境、学习与数据三条线分开，腿式运动单列）→ 第三部 身体（机械臂、轮式、腿式、人形、手、其他身体）→ 第四部 部件与供应链（关节、感官、能量与算力、软件底座、供应链地图）→ 第五部 大脑（基础模型五层地图、数据、世界模型、从演示到部署）→ 第六部 场景（工厂仓库、户外与危险环境、医院与家庭、自动驾驶、算账）→ 第七部 牌桌（工业机器人与部件公司、移动与人形公司、模型与平台公司）→ 结语（未解决的问题）→ 附录（时间线、公司表、部件表、术语表、资料来源、待核实清单）。

### 每章的骨架

- 开头三段内交代本章回答什么问题；
- "先说结论"小框（3–5 条）；
- 正文：先讲问题和瓶颈，再讲突破和它带来的新限制；术语第一次出现时先给直觉、再给定义；
- 涉及产品时给一张证据阶段表（产品、阶段、用途、证据、日期、未知项）；
- 结尾"证据边界"小框：哪些是公开证据不足的，哪些各方说法不一。

### 写作流程（每章）

研究（新增和变更先进事实库）→ 写 → 按十维自评（原提示词 11 的八维，加"准确""实证"两维）→ 改最弱的地方 → 事实核查（每个数字回事实库）→ 跑 `排版/检查书稿.py` 到问题清零 → 记 `策划/编辑记录.md` → 下一章。

### 图

只用自己根据公开数据画的示意图（TikZ，灰阶，纸书黑白印也清楚），图注写数据来源；不用产品照片，不用 AI 生成图。
