# 内容简报（对应提示词 9）：写每一章时对照这一份

## 一、声音和语气
- 像一个在机器人公司干过几年的朋友，坐下来边画边讲。不端着，不卖弄，不煽情。
- 阅读难度：高中毕业能读懂正文；"工程师视角"小框面向有理工科基础的读者。
- 第二人称"你"用来指读者；作者自称"我"，少用"我们"。
- 用短句。一段 2–4 句，最长不超过 6 句。
- 打比方要贴切、能落到实处：比方之后马上回到真东西（数字、结构、代码）。
- 下结论要有依据：能给数字就给数字，给数字就给出处；推测就写"推测"并给推理。

## 二、禁用表达（AI 腔、套话、营销腔）
写完每章用 `排版/检查书稿.py` 扫一遍，命中就改：
- 在当今……的时代 / 随着……的快速发展 / 在……的背景下
- 值得注意的是 / 需要指出的是 / 不难发现 / 众所周知 / 毋庸置疑 / 不可否认
- 深入探讨 / 深度剖析 / 全方位 / 多维度 / 一站式
- 赋能 / 抓手 / 闭环（指管理意义时）/ 底层逻辑 / 颗粒度 / 打通 / 链路（非技术义）
- 释放潜能 / 游戏规则改变者 / 颠覆性 / 革命性（除非引原话）
- 让我们一起……/ 接下来，让我们……/ 总而言之 / 综上所述 / 总的来说
- 不仅……更是…… / 既是……也是……（同一章最多一次）
- 扮演着重要的角色 / 具有重要意义 / 起到了关键作用
- 首先……其次……最后……（用小标题或编号代替）
- 感叹号（全书控制在个位数）

## 三、结构标准
- 每章 5,000–7,500 字；小标题每 600–1,000 字一个（二级标题用"##"，三级用"###"）。
- 开头：一个具体场景、一个数字或一个问题，3 句内抓住人。
- "工程师视角"小框：用 `::: engineer` 包起来，标题写在第一行"**标题**"；内容可以有公式、代码、计算。大众读者可跳过，正文不能依赖它。
- 章末依次是：`::: takeaway`（本章一句话）、`::: career`（转行者笔记：对应岗位、要补的课、一个小练习）、`::: try`（动手环节）。
- 结尾 2–3 句把读者带进下一章。
- 图：用 `![图注](图/xx.pdf){#fig:xx}` 引用；正文提到"图 x-y"。

## 五、比同类书做得更好的 5 件事
1. 每个数字能追溯（附录 E 列来源）。
2. 每章都能"拿走一样东西"（速读卡、对照表、清单、计划表）。
3. 讲清楚"表演"和"干活"的区别，不跟风吹。
4. 风险、短板、安全事件照实写，不当公司宣传册。
5. 转行内容落到仓库名、命令、岗位关键词，而不是"多学习多实践"。

## 七、事实规则
- 数字只从 `资料/事实库.md` 取；新数字先进事实库、带出处，再进正文。
- 公司自述的"全球首例""第一"写成"宇树称……"或"据招股书……"。
- 推测要标出来："我的估算是……，算法是……"。
- 不写：未证实的传闻、具体薪资、荐股。
