# 90 天上车：不买真机也能做的三个项目

想转行做机器人，第一个念头往往是：得先买一台机器人吧？

不用。一台装了 Ubuntu 的电脑，加上宇树和开源社区公开的代码，你就能在 90 天里做出三个拿得出手的项目：在仿真里让一只机器狗站起来，训练一个会走路的策略，再做一个模仿学习的小项目。

这三个项目对应本书的三条主线：第 9 章的低层控制，第 12 章的强化学习和仿真到真机，第 15 章的模仿学习。做完它们，面试时你能讲半小时，而且讲的都是自己动手踩过的坑。

## 先准备好

**电脑。** 推荐装 Ubuntu 22.04（宇树的 ROS 2 仓库推荐这个版本，和 ROS 2 Humble 配套）。项目一只需要 CPU；项目二用 Isaac Gym 或 Isaac Lab 训练，需要一块较新的英伟达 RTX 显卡，具体型号和显存要求以英伟达官方文档为准；没有合适的显卡，可以按小时租云端 GPU。

**基本功。** Python 会写、会用 Git、会在命令行里装软件、看报错。不熟的话，先花一两周补上，这比任何机器人知识都基础。

**一个记录本。** 从第一天起，把每一步做了什么、报了什么错、怎么解决的记下来。三个月后，这本记录会变成你作品集的骨架。

**安全提醒。** 这三个项目都在仿真里做，不会伤到人。将来有机会碰真机时，记住第 9 章的规矩：先吊起来，增益调小，手边放急停。

## 项目一（第 1–30 天）：在仿真里让一只机器狗站起来

**目标**：用和真机一模一样的接口，在 MuJoCo 仿真器里控制一只 Go2 的 12 个关节，让它从趴着平稳地站起来；然后改动刚度和阻尼，观察它的变化，画出曲线，写一份小报告。

**用到的开源代码**：

- `unitree_sdk2_python`：宇树 SDK 的 Python 接口。
- `unitree_mujoco`：宇树基于 MuJoCo 的仿真器。它的设计目标是：用 unitree_sdk2、unitree_ros2 或 unitree_sdk2_python 写的控制程序，先在仿真里跑通，再原样搬到真机上。

**步骤**（以仓库说明为准）：

1. 安装 `unitree_sdk2_python` 和仿真要用的两个库：

   ```bash
   cd unitree_sdk2_python
   pip3 install -e .
   pip3 install mujoco pygame
   ```

2. 打开 `unitree_mujoco/simulate_python/config.py`，确认这三行是这样写的：

   ```python
   ROBOT = "go2"
   DOMAIN_ID = 1
   INTERFACE = "lo"
   ```

   DDS 域号 1、回环网卡 `lo`，表示“这是仿真”。

3. 启动仿真器：

   ```bash
   cd ./simulate_python
   python3 ./unitree_mujoco.py
   ```

4. 另开一个终端，先跑测试程序 `python3 ./test/test_unitree_sdk2.py`。它会打印机器狗的姿态和位置，并给每个电机加 1 N·m 的扭矩——看到数据在跳、腿在动，说明通信通了。
5. 运行仓库 `example` 目录里 Go2 的站起示例（Python 版是 `stand_go2.py`）。看它怎么用第 9 章讲的五个数（`q`、`dq`、`kp`、`kd`、`tau`）把机器狗扶起来。

**你要做的改动**：

- 把 `kp` 分别改成原来的 0.3 倍、1 倍、3 倍，`kd` 同理，记录站起过程中某个膝关节“目标角度”和“实际角度”的曲线，画在一张图里。你会亲眼看到第 9 章说的“刚度太小站不起来，太大会抖”。
- 用 `terrain_tool` 生成一段台阶或崎岖地形，看看只用固定姿势站着的机器狗遇到地形变化会怎样——这会让你理解为什么需要第 11、12 章的控制方法。

**交付物**：一个 GitHub 仓库（代码 + README）、一段 30 秒的录屏、一张 kp/kd 对比曲线图、一段 300 字的“我观察到了什么”。

**一个值得写进报告的细节**：仓库说明里写着，从仿真切换到真机，只需要把 DDS 域号从 1 改成 0、把网卡从 `lo` 换成连接机器人的那块网卡，比如 `python3 ./stand_go2.py enp3s0`。同一段代码，仿真和真机通用。面试时讲清楚这一点，说明你理解“部署”是怎么回事。

## 项目二（第 31–60 天）：训练一个会走路的策略

**目标**：用强化学习在仿真里训练 G1（或 Go2）按速度指令行走，在第二个仿真器里验证，再做一组对照实验，证明你理解奖励和域随机化在干什么。

**用到的开源代码**（二选一）：

- `unitree_rl_gym`：基于 Isaac Gym 和 legged_gym，支持 Go2、H1、H1-2、G1。资料多、上手快。
- `unitree_rl_lab`：基于英伟达新一代的 Isaac Lab，支持 Go2、H1、G1（29 自由度）。更新，但对环境要求更高。

**以 unitree_rl_gym 为例的四步**（命令来自仓库说明，任务名以仓库为准）：

```bash
# 1 训练
python legged_gym/scripts/train.py --task=g1
# 2 回放并导出策略
python legged_gym/scripts/play.py --task=g1
# 3 在 MuJoCo 里做仿真到仿真的验证
python deploy/deploy_mujoco/deploy_mujoco.py g1.yaml
# 4 上真机（有真机时才做；机器人须先进入调试模式）
python deploy/deploy_real/deploy_real.py {网卡名} g1.yaml
```

训练时记得按仓库说明关掉实时可视化，否则会慢很多。

如果用 `unitree_rl_lab`：在 Isaac Lab 里训练 `Unitree-G1-29dof-Velocity` 这类任务，然后启动 `unitree_mujoco` 选择 G1，配合它提供的控制程序做仿真到仿真的验证。具体步骤见仓库说明。

**你要做的对照实验**（挑两个做）：

1. **改奖励**：把“脚腾空时间”的奖励权重调大三倍或改成零，重新训练，比较步态。
2. **关掉域随机化**：把摩擦、质量随机化关掉训练一个版本，再在 MuJoCo 里把地面摩擦调低，比较两个版本谁更容易摔。
3. **加推力**：在验证时给机身施加随机推力，统计两个版本各能扛住多大的推力。
4. **换指令**：测试策略在训练时没见过的速度指令下的表现。

**交付物**：训练曲线截图、两个版本的对比视频、一张表格（版本、设置、成功率或摔倒次数）、一页“仿真到仿真的过程中我遇到了什么问题”。

最后这一页最值钱。Sim2Sim 时，你几乎一定会遇到问题：关节顺序对不上、默认姿势不一致、控制频率不匹配、PD 参数不同。每一个问题，都是你将来上真机会遇到的问题的预演。把它们写清楚，面试官会知道你是真做过的。

## 项目三（第 61–90 天）：一个模仿学习小项目

**目标**：用示范数据训练一个操作策略，在仿真里评测它的成功率，观察示范数量和成功率的关系。

**用到的开源代码**：Hugging Face 的 LeRobot。它实现了 ACT、Diffusion 等模仿学习方法，以及 π0、SmolVLA、GR00T 等多种 VLA 模型；提供 `lerobot-train` 训练、`lerobot-eval` 在仿真基准（README 里列了 LIBERO 和 MetaWorld）上评测。训练命令长这样（来自仓库说明）：

```bash
lerobot-train \
  --policy.type=act \
  --dataset.repo_id=lerobot/aloha_mobile_cabinet
```

**步骤**：

1. 按文档装好 LeRobot，挑一个带仿真评测的基准任务，下载对应的示范数据集。
2. 用 ACT 训练一个策略，用 `lerobot-eval` 评测成功率。
3. 只用 10%、30%、100% 的示范数据各训练一次，画一条“示范数量—成功率”曲线。
4. 换成 Diffusion 再做一次，比较两种方法。

**进阶选项**（选做）：

- 宇树的 `unitree_lerobot` 把 G1 的数据转换、LeRobot 训练和真机部署串了起来；`unitree_sim_isaaclab` 提供了和真机接口一致的 G1 仿真环境。有余力可以试试在人形机器人上做。
- 想碰真硬件，亚马逊上有一类给 LeRobot 用的开源低成本机械臂套件（SO-ARM101），三四百美元一套。用两只臂一主一从做遥操作，采几十条示范，训练一个“把积木放进盒子”的策略——这是很多人入门具身智能的第一个真机项目。

**交付物**：成功率曲线、两种方法的对比、失败案例的视频和分析（失败比成功更能说明你的理解）。

## 作品集怎么写

三个项目做完，把它们整理成一个作品集。几条建议：

- **每个项目一个仓库，README 写清四件事**：要解决什么问题，用了什么方法，结果如何（有数字、有图、有视频），踩了哪些坑。
- **视频比文字有说服力**。每个项目剪一段一两分钟的视频，正常速度，一镜到底更好（第 13 章的五个问题，面试官也会问你）。
- **写出失败**。“我以为是奖励的问题，后来发现是关节顺序搞反了”这种故事，比“一次就成功了”可信得多。
- **写一篇总结文章**，发在技术社区或个人博客上。会讲清楚，是工程师很重要的能力。

## 面试常被问到的问题

按方向列一些，括号里是本书对应的章节，答案要点都在那里：

**基础**

- 为什么腿足机器人常用低减速比的关节？（第 6 章：反驱性、抗冲击、电流估力）
- PD 控制里，`kp` 和 `kd` 分别调大会怎样？（第 9、11 章）
- 解释一下支撑多边形和动态平衡。为什么对角小跑是动态稳定的？（第 10 章）

**运动控制**

- MPC 里为什么只执行第一步？（第 11 章：滚动优化）
- 单刚体模型忽略了什么？什么时候会出问题？（第 11 章）

**强化学习**

- 你的观测和动作是什么？为什么动作输出关节目标角度，而不是直接输出扭矩？（第 12 章）
- 遇到过奖励被“钻空子”吗？怎么发现、怎么解决？（第 12 章）
- 为什么要做 Sim2Sim？你在 Sim2Sim 时遇到了什么问题？（第 12 章、本章项目二）
- 域随机化随机化了哪些参数？范围怎么定？（第 12 章）

**感知和大模型**

- 腿足机器人的高度图和自动驾驶的地图有什么不同？（第 14 章）
- VLA 的动作头有哪几种做法？为什么要输出动作块？（第 15 章）
- 你觉得具身大模型目前最大的瓶颈是什么？（第 15 章：数据）

**项目深挖**

- 你的项目里最难的一个问题是什么？怎么定位的？
- 如果给你一台真机，你的策略部署上去，最可能先出什么问题？

## 学习资源

本书附录 C 有一份带说明的资源清单。这里只列最核心的几样：

- **书**：Lynch 和 Park 的《现代机器人学》（*Modern Robotics*，有免费的在线版和配套课程）；梶田秀司《人形机器人》；Sutton 和 Barto 的《强化学习》（第二版，作者公开了在线版）。
- **课**：Russ Tedrake 的 *Underactuated Robotics*（免费在线，讲腿足和不稳定系统）。
- **代码**：宇树在 GitHub 上的 unitreerobotics 组织（SDK、ROS 2、MuJoCo 仿真、强化学习、遥操作、LeRobot 适配都在这里）；legged_gym；Hugging Face 的 LeRobot。
- **文档**：宇树官方的开发者文档中心；Isaac Lab 和 MuJoCo 的官方文档。
