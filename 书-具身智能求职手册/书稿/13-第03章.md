# 快速见效：把招聘启事拆成能力清单

一条招聘启事三四百字，大多数人只认真看两处：薪资和学历。看完心里只剩一个模糊的判断：“好像够不着”或者“好像能试试”。

这一章教你把启事拆开读，读出三样东西：这个岗位每天干什么，门槛到底卡在哪，团队真正缺什么。然后用一个小脚本，把你收集的十几条启事一起统计，得到一份属于你自己的差距清单。

今天就能做完，做完你会知道接下来三个月该先补哪几样。

## 一条启事的三段

几乎所有启事都分三段：**岗位职责、任职要求、加分项**。三段各说明一件事。

拿一条按常见写法改写的运动控制岗位来看（不对应任何一家公司）：

> **运动控制算法工程师**
>
> 岗位职责：1. 负责足式机器人（四足/人形）运动控制算法的研发与真机调试；2. 开发 MPC、WBC 等控制框架，提升机器人在复杂地形下的稳定性；3. 编写控制 SDK 与文档。
>
> 任职要求：1. 硕士及以上学历，控制、机械电子、自动化等相关专业；2. 熟悉机器人运动学与动力学建模，熟悉 PID、LQR、MPC；3. 熟练使用 C++，熟悉 Linux 和 ROS 2；4. 有足式机器人真机调试经验者优先；5. 有 RoboMaster 等机器人竞赛经历者优先。

**岗位职责说的是“你每天干什么”，也透露了团队眼下在解决什么问题。** 这一条里，“复杂地形下的稳定性”说明他们的机器人在平地上已经能走了，现在要解决的是台阶、斜坡、碎石路；“编写控制 SDK 与文档”说明控制算法要交给别人（客户或者别的团队）调用，你的代码要写得让别人看得懂。

**任职要求是筛选门槛。** 学历和专业是第一道筛子，往往由 HR 或系统按关键词过；技能清单是第二道，由面试官验证。

**加分项往往是团队最痛的地方。** “真机调试经验”和“机器人竞赛经历”都指向一件事：他们需要不怕碰硬件、能在真机上把问题找出来的人。这一条在面试里很可能被追问：“你调过真机吗？遇到过什么问题？”

::: examiner
**考官视角：加分项不是可有可无**

候选人多的时候，面试官会先挑加分项沾边的人。如果你不满足加分项，就在简历和面试里拿一个“最接近的经历”顶上去。比如没调过机器人，但调过汽车的线控底盘，或者在仿真里复现过一个真机问题。第 13 章讲具体写法。
:::

## “精通、熟悉、了解”各是什么分量

启事里描述技能的动词是有分量的，面试官会按这个分量来考。

- **精通**：能独立做项目，面试被连续追问三层不倒。比如“精通 C++”，要能讲清楚移动语义、智能指针的所有权、多线程里的数据竞争怎么查。
- **熟悉**：用过、做过、能讲清楚原理和取舍。比如“熟悉 MPC”，要能写出优化问题的形式，说清楚预测时域怎么选、约束怎么加。
- **了解**：知道是什么、为什么用、读过文档或论文。比如“了解 VLA”，能说出它的输入输出和几种代表模型即可。

还有一种常见写法：“掌握 WBC、MPC、强化学习、状态估计**中至少一个方向**”。意思是要你在一个方向上够深，而不是每样都懂一点。准备的时候，选一个方向做到“熟悉”以上，其他的做到“了解”。

## 藏在字里行间的信息

除了明写的要求，启事里还藏着一些信息，能帮你判断这个岗位和这家公司。

- **工具名透露技术栈**。写 Isaac Lab、MuJoCo，说明在用新一代仿真器训练；写 Gazebo、ROS 1，技术栈可能偏老。
- **“量产”“供应链”“DFM”**：公司已经在批量交付，工程岗位多，节奏偏稳。
- **“数据采集”“遥操作”“数据闭环”**：公司在做具身大模型，数据相关的岗位会持续招。
- **“能接受出差”“现场部署”**：岗位要跑客户现场。对有些人是缺点，对喜欢和客户打交道的人反而是机会。
- **写了很长的技术要求、却没写具体职责**：可能是团队还在搭建，你进去要做的事会比描述的多。

## 用脚本统计十几条启事

一条启事有偶然性，十几条放在一起看才有规律。随书代码里有一个小工具 `jd_check.py`，它做三件事：统计每项技能在多少条启事里出现；和你自己的技能对照；按出现次数列出你最该补的几项。

**第一步，收集启事。** 在招聘网站、公司官网上找你目标岗位的启事，10–30 条，尽量来自不同的公司。把全文复制进一个文本文件，启事之间用单独一行 `---` 隔开。只给自己用、不外传，这样做没有问题。

**第二步，写下你的技能。** 新建一个文本文件，一行写一项你会的技能，写法随意，“ROS2”“ROS 2”都认。

**第三步，运行：**

```bash
python jd_check.py --jd 我收集的启事.txt --me 我的技能.txt
```

随书代码里带了一份示例数据：10 条按常见写法改写的启事，覆盖运控、强化学习、大模型、SLAM、嵌入式、测试、数据采集、机械、系统软件、解决方案 10 个岗位；还有第 2 章那位自动驾驶感知工程师的技能清单。用示例数据跑一遍，输出的开头和结尾是这样的：

```text
共 10 条启事

技能                出现  占比  你有吗
真机调试/部署       5     50%   ✗
ROS/ROS 2           5     50%   ✓
Linux               4     40%   ✓
足式/人形运控       3     30%   ✗
C++                 3     30%   ✓
……
你最该补的 10 项（按出现次数排）：
   1. 真机调试/部署（5/10 条启事提到）
   2. 足式/人形运控（3/10 条启事提到）
   3. 测试/验证（3/10 条启事提到）
   4. 运动学（2/10 条启事提到）
   5. 动力学（2/10 条启事提到）
   ……
你已经覆盖六成以上要求的启事：4/10 条

学历：
  提到本科：7/10 条
  提到硕士：3/10 条
  提到博士：0/10 条
  提到工作年限的 4 处，中位数 3 年
```

示例数据故意横跨 10 个岗位，所以每项技能的占比都不高。你自己用的时候，只收集目标岗位的启事，规律会清楚得多。

这个工具靠一张关键词表匹配，粗糙但够用。它会漏，也会误判，比如“测试”这个词在很多启事里只是顺带一提。看到可疑的结果，回到原文核对一下。你的方向有它不认识的词，就照着格式往词表里加一行：

```python
SKILLS = {
    "MPC": r"\bmpc\b|模型预测控制",
    "WBC": r"\bwbc\b|全身控制|whole[- ]body",
    # 在这里加你的词：名字和正则，正则不区分大小写
}
```

## 把差距排成计划

拿到差距清单以后，别从第一项开始一口气学下去。先把每项差距分进三个筐：

| 筐 | 例子 | 怎么办 |
|-------|-----------------|-----------------|
| 两周能补 | Docker、MuJoCo 入门、ROS 2 基本用法 | 马上做，做完写进简历 |
| 一两个月能补 | 运动学和动力学、强化学习基础、实时系统 | 排进 90 天计划，配一个作品集项目 |
| 半年以上或补不了 | 学历、足式机器人真机经验、顶会论文 | 不硬补；用别的东西顶上，或者换个目标岗位 |

: 表 3-1　差距的三个筐

**优先级 = 出现次数 × 补起来有多快。** 出现得多、补得快的放最前面。

用示例结果试一下。对那位自动驾驶感知工程师来说：

- “真机调试/部署”出现得最多，但没有机器人很难补。可以换个说法：车辆上的传感器标定、实车路测排障，都是“真机调试”，简历里要这样写；再用第 11 章的项目在仿真里补“机器人怎么调”。
- “运动学”“动力学”放进一两个月的筐，配第 12 章的机械臂项目。
- “足式/人形运控”需要半年以上，暂时不补，所以第 2 章给这位工程师选的主攻方向是 SLAM，不是运控。

::: takeaway
差距是能列出来、能排优先级的。先补出现次数多、补得快的，补不了的就换个说法或者换个岗位。
:::

::: career
**转行者笔记：别被“优先”吓退**

很多人看到“有足式机器人经验者优先”就不敢投了。“优先”的意思是有更好，没有也能投。真正的硬门槛一般写在任职要求的前两条。加分项一条都不满足，也值得投十家试试，面试本身就是最好的调研。
:::
