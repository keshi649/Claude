# 所有岗位都会问的基础

不管投哪个岗位，技术面试的前二十分钟往往长得差不多：一道旋转或坐标变换的题，一道 C++ 或多线程的题，一道和控制频率、通信有关的题，再手写一小段代码。

这些题不难，但答不好会直接出局：面试官会觉得你连机器人工程的地基都没有，后面的项目讲得再漂亮也不敢要。

这一章先给一张基础知识的地图，再给 12 道最常见的题和参考答案。最后有一个 30 分钟的自测，测完你就知道自己的地基牢不牢。

## 面试题和参考答案

### 4.1　旋转矩阵、欧拉角、四元数、轴角，各有什么优缺点？什么是万向锁？ {#q4-1}

**一句话**：四个都是表示三维旋转的方法，各有擅长的场合：算变换用旋转矩阵，存储和插值用四元数，优化里用轴角（旋转向量），给人看用欧拉角。

- **旋转矩阵**：9 个数，满足正交、行列式为 1 的约束。旋转一个向量、把几个旋转连起来都只要矩阵乘法，很直接；缺点是冗余，数值误差积累以后会不再正交，需要重新正交化。
- **欧拉角**：3 个数（比如偏航、俯仰、横滚），直观；缺点是有 12 种转轴顺序，团队之间经常搞混，插值不平滑，还有万向锁。
- **四元数**：4 个数，单位长度。没有万向锁，连乘计算量小，插值平滑。要注意 $q$ 和 $-q$ 表示同一个旋转（双重覆盖），比较两个姿态时要考虑这一点。
- **轴角/旋转向量**：3 个数，方向是转轴，长度是转角。适合表示小的旋转增量，所以优化和滤波里常用它做“误差状态”。

**万向锁**：以“偏航-俯仰-横滚”（ZYX）顺序为例，俯仰转到 ±90° 时，第一次和第三次旋转的轴重合了，偏航和横滚变成同一个效果，丢掉一个自由度。这时姿态还在，但欧拉角解不唯一，在这附近数值会剧烈跳变。

**考官想听到**：万向锁能举出具体的角度；知道 $q$ 和 $-q$ 的问题；知道什么场合用哪种表示。

### 4.2　两个坐标系之间的变换怎么表示？$T_{AB}$ 的逆是什么？怎么把相机看到的点变到机器人基座坐标系？ {#q4-2}

**一句话**：用 4×4 的齐次变换矩阵把旋转 $R$ 和平移 $p$ 写在一起；求逆不用对整个矩阵求逆，直接写出来：
$$T = \begin{bmatrix} R & p \\ 0 & 1 \end{bmatrix}, \qquad T^{-1} = \begin{bmatrix} R^\top & -R^\top p \\ 0 & 1 \end{bmatrix}$$

约定 $T_{AB}$ 表示“坐标系 B 在坐标系 A 里的位姿”，它把 B 里的点变到 A 里：$p_A = T_{AB}\, p_B$（点写成齐次坐标）。这样写的好处是下标能“消掉”：
$$p_{\text{基座}} = T_{\text{基座},\text{相机}}\; p_{\text{相机}}, \qquad T_{\text{基座},\text{相机}} = T_{\text{基座},\text{法兰}}\; T_{\text{法兰},\text{相机}}$$

其中 $T_{\text{基座},\text{法兰}}$ 来自正运动学，$T_{\text{法兰},\text{相机}}$ 来自手眼标定。

团队里最常见的错误是两个人对 $T_{AB}$ 的含义理解相反。所以第一件事是把约定写进文档。ROS 2 的 tf2 里，`lookupTransform(target, source)` 返回的就是把 source 坐标系里的数据变到 target 坐标系的变换。

**考官想听到**：不用矩阵求逆就能写出逆变换；下标约定清楚；能说出手眼标定在这条链里的位置。

### 4.3　两个姿态之间怎么插值？为什么不能直接对四元数做线性插值？ {#q4-3}

**一句话**：用球面线性插值（slerp），沿着单位球面上的大圆走，角速度均匀。

对四元数的四个分量直接线性插值，中间结果不是单位四元数，要再归一化（这叫 nlerp）。nlerp 的路径是对的，但角速度不均匀：两头慢中间快。slerp 的公式是：
$$q(t) = \frac{\sin((1-t)\Omega)}{\sin\Omega}\, q_0 + \frac{\sin(t\Omega)}{\sin\Omega}\, q_1, \qquad \cos\Omega = q_0 \cdot q_1$$

两个实现细节：一是如果 $q_0 \cdot q_1 < 0$，先把 $q_1$ 取反，否则会绕远路走 360° 减去那个角度；二是两个姿态非常接近时 $\sin\Omega \to 0$，改用 nlerp 防止除零。

**考官想听到**：取反走短路径；接近时的数值处理；知道 nlerp 在很多实时场合也够用。

### 4.4　什么是雅可比矩阵？在机器人里有什么用？什么叫奇异？ {#q4-4}

**一句话**：雅可比 $J(q)$ 把关节速度映射成末端速度：$v = J(q)\,\dot q$。

它的用处至少有四个：

1. **速度控制**：想让末端以某个速度走，就解 $\dot q = J^{-1} v$（或者伪逆）。
2. **数值逆运动学**：每次迭代用 $J$ 把末端误差变成关节修正量。
3. **力的映射**：末端要施加力 $F$，关节需要的力矩是 $\tau = J^\top F$。这条可以用虚功原理推出来：$\tau^\top \dot q = F^\top v = F^\top J \dot q$ 对任意 $\dot q$ 成立。
4. **可操作度**：$J$ 的奇异值告诉你末端往哪个方向容易动、哪个方向难动。

**奇异**是 $J$ 降秩：末端在某个方向上动不了，想硬让它动，关节速度会趋向无穷大。机械臂完全伸直、两个手腕关节的轴重合，都是典型的奇异位形。工程上常用阻尼最小二乘处理：$\dot q = J^\top (J J^\top + \lambda^2 I)^{-1} v$，代价是在奇异附近跟踪误差变大。第 12 章的项目五会实际跑一遍：伪逆在接近伸直时把关节速度推到几千 rad/s，阻尼最小二乘一直不超过 3 rad/s。

**考官想听到**：$\tau = J^\top F$ 能推出来；能举出奇异位形的例子；知道阻尼最小二乘和它的代价。

### 4.5　最小二乘怎么解？什么时候不该用正规方程？ {#q4-5}

**一句话**：求 $\min \lVert Ax - b \rVert^2$，正规方程给出 $x = (A^\top A)^{-1} A^\top b$，但数值上更稳的是用 QR 分解或 SVD。

问题出在 $A^\top A$ 的条件数是 $A$ 的条件数的平方。$A$ 本来就有点病态（比如标定时数据都挤在一个小范围里），平方以后精度就丢了。QR 分解直接在 $A$ 上做，不会平方条件数；SVD 最稳，还能处理 $A$ 不满秩的情况，这时给出的是伪逆解。

两个常见的变体也要会：**加权最小二乘**，给可信的测量更大的权重；**带正则的最小二乘**，在目标里加 $\lambda^2 \lVert x \rVert^2$，它和上一题的阻尼最小二乘是同一件事。

**考官想听到**：条件数平方；知道什么时候用 SVD；能把正则化和阻尼最小二乘联系起来。

### 4.6　C++ 的 unique_ptr、shared_ptr、weak_ptr 有什么区别？什么情况下还会内存泄漏？ {#q4-6}

**一句话**：unique_ptr 独占所有权，shared_ptr 引用计数共享所有权，weak_ptr 不拥有、只观察，用来打破循环引用。

- `unique_ptr` 不能拷贝，只能移动，开销和裸指针一样，默认首选。
- `shared_ptr` 每次拷贝都要原子地加减引用计数，有开销；计数归零时释放。
- `weak_ptr` 不增加计数，用之前要 `lock()` 成 shared_ptr，对象已经没了就得到空指针。

用了智能指针还会泄漏的典型情况是**循环引用**：父节点用 shared_ptr 指向子节点，子节点也用 shared_ptr 指回父节点，两个计数永远不归零。子节点指回父节点的那一个改成 weak_ptr 就好了。另一个常见坑是回调里捕获了 `shared_from_this()`，回调没注销，对象就一直活着。

机器人代码里还要加一条：**实时控制循环里别拷贝 shared_ptr、别分配内存**。原子操作和内存分配的耗时都不确定，会让 1 ms 的控制周期偶尔超时。

**考官想听到**：循环引用和解法；shared_ptr 的开销；实时循环里的禁忌。

### 4.7　std::move 做了什么？移动以后原来的对象还能用吗？ {#q4-7}

**一句话**：`std::move` 什么也没移动，它只是把一个对象转换成右值引用，让编译器去选择移动构造或移动赋值。

真正“移动”的是移动构造函数：它把资源（比如堆上的缓冲区指针）从源对象拿过来，再把源对象里的指针置空，省掉一次深拷贝。移动之后，源对象处于“有效但未指定”的状态：可以析构、可以重新赋值，但不应该再读它的内容。

两个相关的点：函数按值返回局部对象时，编译器通常直接做返回值优化，连移动都省了，这时再写 `return std::move(x);` 反而可能阻止优化；一个类自己管理资源时，要按“五法则”把析构、拷贝构造、拷贝赋值、移动构造、移动赋值一起考虑。

**考官想听到**：move 只是类型转换；被移动对象的状态；返回值优化。

### 4.8　互斥锁、条件变量、原子变量怎么选？实时控制线程里为什么尽量不加锁？ {#q4-8}

**一句话**：互斥锁保护一段共享数据，条件变量用来“等某个条件成立”，原子变量适合单个变量的无锁读写。

条件变量要配合互斥锁使用，等待必须放在 `while` 循环里检查条件，因为存在虚假唤醒。

实时线程里少用锁，原因是**优先级反转**：低优先级线程拿着锁，被中优先级线程抢占，高优先级的控制线程等锁，结果被一个毫不相干的中优先级线程间接卡住。1997 年火星探路者号反复重启，原因就是一次优先级反转。

常见的替代做法：

1. 单生产者单消费者的**无锁环形缓冲区**，控制线程和通信线程之间传数据；
2. **双缓冲**：写线程写一份，写完原子地切换指针；
3. 实在要用锁，用支持**优先级继承**的互斥锁，或者在控制线程里只用 `try_lock`，拿不到就用上一周期的数据。

**考官想听到**：优先级反转能讲清楚；知道无锁队列和双缓冲；知道条件变量的虚假唤醒。

### 4.9　一个 1 kHz 的控制循环，怎么保证它真的每 1 ms 跑一次？怎么测？ {#q4-9}

**一句话**：用绝对时间睡眠、实时调度和实时内核，循环里不做任何耗时不确定的事；用时间戳统计周期的抖动和最坏延迟。

具体做法：

- 用 `clock_nanosleep` 加 `TIMER_ABSTIME`，按“下一个周期的绝对时间点”睡，而不是每次睡 1 ms。后者会把每次的处理时间累积成漂移。
- 线程设成 `SCHED_FIFO` 实时调度，给一个高优先级；系统用 PREEMPT_RT 实时内核；把控制线程绑到一个隔离出来的 CPU 核上。
- 启动时 `mlockall` 锁住内存，避免运行中缺页；预先分配好所有内存。
- 循环里不打日志、不读写文件、不分配内存，日志通过无锁队列交给另一个线程写。

测的方法：每个周期记录时间戳，统计实际周期的分布，重点看最坏值而不是平均值。系统层面可以先用 `cyclictest` 看这台机器的调度延迟。

**考官想听到**：绝对时间睡眠；最坏延迟比平均值重要；能说出两三条“循环里不能做的事”。

### 4.10　ROS 2 的话题、服务、动作有什么区别？QoS 的 reliable 和 best effort 怎么选？ {#q4-10}

**一句话**：话题是持续的数据流，服务是一问一答，动作是有反馈、能取消的长任务。

- **话题**（topic）：发布订阅，适合传感器数据、状态、控制指令。
- **服务**（service）：请求响应，适合查询参数、触发一次性的操作。
- **动作**（action）：发一个目标，过程中持续反馈，可以中途取消，适合“走到某个位置”“抓起某个物体”这种要花几秒到几分钟的任务。

QoS 里最常被问的是可靠性：

- **reliable**：丢了会重传，保证送到。适合控制指令、配置、状态切换。
- **best effort**：丢了就丢了。适合高频的传感器数据，比如图像和 IMU，你要的是最新的一帧，重传一帧旧的没有意义。

一个常见的坑：订阅方设成 reliable、发布方是 best effort，两边 QoS 不兼容，**根本连不上**。程序不会崩，只在日志里打一条不太显眼的“QoS 不兼容”警告，表现就是收不到数据。排查的时候用 `ros2 topic info -v` 看两边的 QoS。

**考官想听到**：三种通信的适用场景；QoS 不兼容导致收不到数据；为什么传感器数据用 best effort。

### 4.11　DDS 是什么？为什么同一网段里两套 ROS 2 程序会“串台”？怎么隔离？ {#q4-11}

**一句话**：DDS 是 ROS 2 底下的通信中间件，它会在局域网里自动发现其他参与者，所以同一网段、同一个域里的程序会互相看见。

DDS 的自动发现靠组播：每个参与者启动时广播“我在这里，我发布什么、订阅什么”，匹配上就直接通信，不需要中心节点。这很方便，但两台机器人、或者仿真和真机放在同一个网段里，就可能互相收到对方的话题。

隔离的办法有三种：

1. **不同的域号**（`ROS_DOMAIN_ID`），不同域之间互相看不见。《拆解宇树》第 19 章讲过，宇树的仿真器用域号 1、真机用域号 0，切换时只改这个数；
2. 只在本机通信：较新的 ROS 2 版本把环境变量 `ROS_AUTOMATIC_DISCOVERY_RANGE` 设成 `LOCALHOST`；
3. 指定 DDS 使用的网卡，或者配置只和白名单里的地址通信。

**考官想听到**：自动发现的机制；域号；仿真和真机怎么隔离。

### 4.12　手写一个带抗积分饱和的 PID 控制器 {#q4-12}

**一句话**：输出限幅以后要停止积分（或者往回退），否则积分项会越积越大，退出饱和时严重超调。

```python
class PID:
    def __init__(self, kp, ki, kd, out_min, out_max, d_alpha=0.1):
        self.kp, self.ki, self.kd = kp, ki, kd
        self.out_min, self.out_max = out_min, out_max
        self.d_alpha = d_alpha          # 微分项一阶低通的系数
        self.integral = 0.0
        self.prev_meas = None
        self.d_filt = 0.0

    def update(self, target, meas, dt):
        err = target - meas
        # 对测量值求微分，而不是对误差：目标值突变时不会有“微分冲击”
        d = 0.0 if self.prev_meas is None else -(meas - self.prev_meas) / dt
        self.prev_meas = meas
        self.d_filt += self.d_alpha * (d - self.d_filt)
        out = self.kp * err + self.integral + self.kd * self.d_filt
        if self.out_min < out < self.out_max:
            self.integral += self.ki * err * dt     # 只在不饱和时积分
        return min(max(out, self.out_min), self.out_max)
```

讲代码的时候主动说出三个设计：**条件积分**防止积分饱和；**对测量值求微分**，目标值突变时不会出现微分冲击；**微分项低通滤波**，因为微分会放大测量噪声。积分项乘 $k_i$ 以后再累加，这样在线改 $k_i$ 时输出不会突跳。

**考官想听到**：三个设计都能说出来；知道 $dt$ 要用实际测得的周期；能说出另一种抗饱和方法（反算法，back-calculation）。
