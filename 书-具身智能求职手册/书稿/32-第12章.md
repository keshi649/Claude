## 项目四：卡尔曼滤波融合 IMU 和腿式里程计

**问题**：怎么把 IMU 和腿式里程计融合起来估计机身的位置？脚打滑时怎么办？

**做法**：为了看清原理，用一维的例子，但设置和真机一样。机器人在 30 秒里加速到约 1 m/s、巡航、再减速停下。

- IMU 200 Hz，带 0.08 m/s² 的零偏（滤波器事先不知道）和噪声；
- 腿式里程计 200 Hz 测速度，噪声 0.05 m/s；有三段时间脚在打滑（共 1.2 秒），这时测到的速度多出 0.8 m/s；
- 每 2 秒来一次绝对位置（比如激光雷达定位），噪声 5 cm。

滤波器的状态是位置、速度和 IMU 零偏三个量，用 IMU 做预测，用腿速和绝对位置做更新。打滑检测用卡方检验：

```python
y = z - (H @ x)[0]                    # 新息：测量和预测之差
S = (H @ P @ H.T)[0, 0] + R           # 新息的方差
if gate is not None and H is H_v and y * y / S > gate:
    rejected += 1                     # 马氏距离太大：当成打滑，丢掉这次腿速
    continue
K = (P @ H.T / S).ravel()
x = x + K * y
P = (np.eye(3) - np.outer(K, H)) @ P
```

**结果**：

| 方法 | 位置均方根误差 | 30 秒末位置误差 |
|------------------|-----------|------------|
| IMU 两次积分 | 15.9 m | 35.7 m |
| 腿速积分 | 0.63 m | 0.98 m |
| 卡尔曼滤波，不设门限 | 0.34 m | 0.39 m |
| 卡尔曼滤波，卡方门限 9 | 0.012 m | 0.007 m |

![图 12-1　项目四：灰色区域是脚打滑的时段。不设门限的滤波器被打滑的腿速带偏，等下一次绝对位置来了才拉回来；加了门限以后几乎不受影响](图/f12-卡尔曼.pdf)

零偏估计在 30 秒后是 0.079，真值 0.08。门限一共挡掉 256 个腿速样本，其中 240 个确实是打滑时的，另外 16 个是正常测量里噪声偏大的，误伤了。

**面试时这样讲**：

> 我做了一个 IMU 加腿式里程计的卡尔曼滤波，状态里包括 IMU 的零偏。纯 IMU 积分 30 秒漂了 35 米，因为零偏被积分了两次；融合以后零偏估得很准。但脚打滑时腿速会错得很离谱，滤波器会被带偏，位置误差 0.34 米。加了卡方门限以后，打滑的测量基本都被挡在外面，误差降到 1 厘米左右。门限也有风险：如果滤波器本身已经发散，它会把好的测量也全部拒掉，所以实际系统里要监控被拒的比例。

**可以继续做**：扩展到三维，姿态用误差状态卡尔曼（第 7 章 7.5 题）；用足端力估计接触概率，代替单纯的门限；故意把初始协方差设得很小，复现“门限把好测量全挡掉”的问题。

## 项目五：机械臂逆运动学，伪逆和阻尼最小二乘

**问题**：接近奇异位形时，数值逆运动学会出什么事？阻尼最小二乘能解决多少？

**做法**：用 UR5e 公开的标准 DH 参数写正运动学和几何雅可比。先做两个检查：一是雅可比和有限差分的结果对比，最大差 1.75e-10；二是全零关节角时末端的位置 (−0.8172, −0.2329, 0.0628) m，和手算一致：$x$ 是大臂和小臂长度之和（朝负方向），$y$ 是两个手腕偏移 $d_4$、$d_6$ 之和取负，$z$ 是底座高度 $d_1$ 减去 $d_5$。

然后让末端保持姿态不变，沿着远离肩膀的方向直线往外伸，伸到比手臂够得着的地方还远 1 厘米。每 10 毫秒一个点，每个点最多迭代 5 次逆运动学，分别用普通伪逆和阻尼最小二乘（$\lambda = 0.05$）：

```python
def ik_step(q, T_des, damping):
    T = fk(q)
    e = np.concatenate([T_des[:3, 3] - T[:3, 3], rot_err(T_des[:3, :3], T[:3, :3])])
    J = jacobian(q)
    if damping == 0:
        dq = np.linalg.pinv(J) @ e                                        # 伪逆
    else:
        dq = J.T @ np.linalg.solve(J @ J.T + damping ** 2 * np.eye(6), e)  # 阻尼最小二乘
    return dq, np.linalg.norm(e[:3])
```

**结果**：

| 方法 | 关节速度超过 π rad/s 的步数 | 最高关节速度 | 最大位置误差 |
|--------|---------------|---------|--------|
| 伪逆 | 35 | 3,939 rad/s | 1.57 m |
| 阻尼最小二乘 | 0 | 2.46 rad/s | 23.8 mm |

![图 12-2　项目五：手臂接近伸直时，雅可比的最小奇异值趋近于零，伪逆给出的关节速度飙到几千 rad/s；阻尼最小二乘一直很平稳，代价是够不着时有几厘米的误差](图/f12-逆运动学.pdf)

**面试时这样讲**：

> 我用 UR5e 的 DH 参数实现了正运动学、雅可比和数值逆运动学，雅可比用有限差分验证过。然后让末端往外伸到够不着的地方，对比伪逆和阻尼最小二乘：接近伸直时最小奇异值趋近于零，伪逆的关节速度冲到几千 rad/s，位置也发散了；阻尼最小二乘的关节速度一直在 3 rad/s 以内，代价是目标够不着的时候，有两三厘米的误差。实际系统里还会再加关节速度和关节限位的约束。

**可以继续做**：用零空间投影加一个“远离关节限位”的次要任务；推导 UR 机械臂的解析逆解，和数值解对比；在 MuJoCo 的 UR5e 模型上验证你的正运动学（注意两边的基座坐标系可能不同）。

## 项目六：模仿学习里的“多峰”问题

**问题**：示范里有两种都对的做法时，行为克隆会怎样？怎么解决？

**做法**：一个点状机器人从左边出发，要到右边的目标，路中间有一个半径 1 米的圆形障碍。专家先直着走到障碍物前 1.5 米，再一半从上面绕、一半从下面绕，和起点在哪无关。比较三种学生：

- **A：均方误差回归**：神经网络直接输出“往哪个方向走”；
- **B：方向分类**：把方向离散成 16 格，当分类问题学，每一步选概率最大的格子；
- **C：动作段分类**：把“接下来 8 步的方向”整段当成一个动作，先用 k 均值把示范里的动作段聚成 32 类，再学分类；选中一类，就把这一段走完再重新决定。

C 的关键代码：

```python
V = chunks_of(H, lengths)                 # 每个状态往后 8 步的方向，编码成 (cos, sin)
protos, lab = kmeans(V, N_PROTO, seed)    # 聚成 32 个“动作段原型”
# …… 训练一个分类网络：状态 -> 原型编号 ……
if not plan:                              # 执行时：上一段走完了才重新选
    c = protos[out.argmax().item()]
    plan = list(np.arctan2(c[CHUNK:], c[:CHUNK]))
h = plan.pop(0)
```

**结果**（61 个起点，纵坐标在 −0.3 到 0.3 米之间均匀分布）：

| 示范数 | A 均方误差回归 | B 方向分类 | C 动作段分类 |
|-------|--------------|---------|-----------|
| 40 条 | 撞了 8 次 | 0 次 | 0 次 |
| 200 条 | 撞了 8 次 | 5 次 | 0 次 |

: 表 12-3　项目六的结果

![图 12-3　项目六：从正中间出发，均方误差回归把“上面绕”和“下面绕”平均成了直着走，撞上障碍物；动作段分类选定一种绕法就走到底](图/f12-多峰.pdf)

A 的问题是平均：在分叉点上，一半示范往上、一半往下，平均下来就是直着走。B 能学出“上下各一半”的分布，我们在分叉点 (3.6, 0) 附近看了它的输出，两个方向的概率是 0.57 和 0.43；可它每一步都重新挑，示范一多、两种走法接近五五开以后，就会在两个方向之间来回切换，200 条示范时撞了 5 次。C 选中一段就走完，前后一致，两种情况下都没有撞。这就是 Behavior Transformer、VQ-BeT 用“动作 token”、ACT 一次输出一段动作要解决的问题（第 8 章 8.2、8.4 题）。

**我们没做成的实验**：最开始想用这个项目演示 DAgger。先后试了小车倒立摆（专家是 LQR）和小车循迹（专家是 Stanley 路径跟踪控制器），结果普通的行为克隆都已经 100% 成功：示范里只要有几厘米的纠偏动作，网络就能学会纠偏；我们故意把“上一步的动作”加进输入，想引出“抄袭问题”，也没有出现。结论是：在低维、平滑的任务上，分布偏移不明显，它真正致命的是图像输入和长时序任务。这个失败本身就是一个好的面试素材。

**面试时这样讲**：

> 我做了一个关于示范多峰的小实验：一半示范从上面绕障碍、一半从下面绕。均方误差回归把两种做法平均成直着走，61 次里撞了 8 次；离散成方向分类以后，40 条示范时一次没撞，但 200 条示范时撞了 5 次，原因是它每一步都重新选，会在上下两个方向之间来回切换；把 8 步的动作段聚类成 token 再分类，两种情况都没有撞。另外我也试过用 DAgger，发现在低维任务上普通的行为克隆就已经够好，这让我理解了分布偏移在什么条件下才真正严重。

**可以继续做**：用一个小的扩散模型或混合高斯网络当策略，和 C 比较；加上 ACT 的“时间集成”；把输入换成一张俯视的图像，再试一次 DAgger。

## 把项目整理成别人愿意看的样子

面试官点开你的 GitHub，往往只看一两分钟。这一两分钟里，要让对方看到三样东西：你解决了什么问题，结果是什么，代码能不能跑。

**README 按这个顺序写**（附录 D 有模板）：

1. **一句话**：这个项目回答什么问题；
2. **一张结果图**：放在最上面，不要藏到最后；
3. **怎么跑**：三行命令以内，写清楚 Python 和库的版本；
4. **做了什么对照**：变量是什么，固定了什么；
5. **结论**：带数字；
6. **局限和下一步**：主动说出不足。

**演示视频**：30 到 60 秒，开头三秒就放结果（站起来的机器狗、绕开障碍的轨迹），再讲对照。MuJoCo 自带的查看器可以录屏；没有图形界面的话，把结果曲线做成动画也可以。

**代码的基本卫生**：依赖写版本号；固定随机种子；结果能复现；仓库里不放大文件和密钥；加一个开源许可证。

::: examiner
**考官视角：我们怎么看作品集**

我们最常问的不是“你做了什么”，而是“你为什么这么做”“结果和你预想的一样吗”“不一样的地方你怎么解释”。所以 README 里最好写一句“我原本以为……，结果发现……，原因是……”。这一句话比整个仓库的代码更能说明你会思考。
:::
